Instalación

Deben tener npm instalado. Para eso, sigan las indicaciones en la siguiente página: Downloading and installing Node.js and npm

  1. Instalar las dependencias (copia limpia, recomendado porque usa el archivo de bloqueo):
npm ci

En PowerShell (Windows), usar npm.cmd para evitar bloqueos de npm.ps1:

npm.cmd ci

Si prefieren una instalación local sin archivo de bloqueo, npm install también funciona.

SQLite: la dependencia sqlite3 contiene componentes nativos. Si falla la instalación, comprobar primero la versión de Node.js y la salida del error.

  1. Levantar el servidor:
npm start

Este comando crea la base de datos en SQLite (db.sqlite) y todas las tablas necesarias.

Levantar el servidor

El servidor escucha en el puerto 3000:

curl http://localhost:3000/products

Si no tienen curl, pueden usar Postman o Insomnia.

Rutas canónicas

El servidor monta los routers sin el prefijo /api/v1:

Categorías GET /categories, POST /categories

Reglas

Estas reglas son la especificación del carrito y del cobro. Si una respuesta del servidor no las cumple, esa diferencia es un hallazgo: no se reescribe la regla para que coincida con el código.

Alta de un ítem

CartService.addItemToCart(cartId, productId, quantity) agrega la cantidad solo cuando el producto existe y quantity es un entero mayor que cero que no supera el inventario. Si el producto ya está en el carrito, la cantidad nueva es la suma, y esa suma tampoco puede superar el inventario.

Ítem y carrito de la URL

El ítem que se actualiza con PUT /cart/:cartId/items/:itemId, o se elimina con DELETE /cart/:cartId/items/:itemId, pertenece al carrito indicado en la URL.

Total al consultar el carrito

GET /cart/:cartId/items usa el precio y el taxRate vigentes del producto:

  • subtotal de línea = cantidad × precio
  • impuesto de línea = subtotal de línea × taxRate
  • summary.subtotal = suma de los subtotales de línea
  • summary.totalTax = suma de los impuestos de línea
  • summary.total = summary.subtotal + summary.totalTax

Esa consulta no aplica cupón ni envío. No es el total cobrado.

Cobro

POST /cart/:cartId/checkout. El cupón es opcional:

{ "coupon": { "type": "percent", "value": 0.1, "minSubtotal": 50 } }

type es percent o fixed. Solo se acepta un cupón: si coupon es un arreglo, el cobro se rechaza. El umbral de envío es 50 y la tarifa es 5. Esos valores no viajan en el cuerpo; si el cliente los envía, no se usan. Están en services/pricing.js (SHIPPING_THRESHOLD y SHIPPING_FEE). priceCheckout(items, coupon) es pura: no toca la base de datos. Cada ítem es { quantity, unitPrice, taxRate }.

El cobro se rechaza, sin modificar el inventario, cuando ocurre cualquiera de estas condiciones:

  • el carrito no existe
  • el id de carrito no es numérico
  • el carrito no tiene ítems
  • el carrito ya fue cobrado
  • alguna cantidad no es un entero mayor que cero
  • el inventario de algún producto es menor que la cantidad de esa línea
  • el precio es negativo, o taxRate no está entre 0 y 1
  • el cupón no cumple lo de abajo

Cupón:

  • percent: value es una fracción mayor que 0 y a lo sumo 1 (0.1 es 10 %). Exige minSubtotal mayor o igual que 0. Si el subtotal es menor que ese mínimo, el cobro se rechaza. Si es igual, el cupón aplica.
  • fixed: value es un monto mayor que 0. Se redondea al centavo y después se compara con el subtotal. Si lo supera, el cobro se rechaza. Si es igual, la base queda en 0.
  • No se acumulan. Un cupón fixed no consulta minSubtotal.

El cálculo, en este orden:

  1. El precio unitario se redondea al centavo más cercano. Si el centavo cae exactamente a la mitad, se redondea alejándose de cero. price y taxRate se guardan como FLOAT: un decimal que el binario no representa puede entrar al cálculo ya distinto del valor escrito.
  2. El subtotal de línea es ese precio por la cantidad. El subtotal del pedido es la suma de las líneas.
  3. El descuento se calcula sobre ese subtotal.
  4. El descuento se reparte en el orden de las líneas, en proporción al subtotal de cada una, redondeado al centavo y sin pasar del descuento que todavía no se ha repartido. La última línea recibe el resto. Cada descuento de línea queda entre 0 y el subtotal de esa línea, y la suma es el descuento del pedido.
  5. El impuesto de cada línea es (subtotal de línea − descuento de línea) × taxRate, redondeado al centavo. El impuesto del pedido es la suma. El impuesto va después del descuento.
  6. La base es subtotal − descuento. Si la base es mayor o igual que 50, el envío es 0. Si es menor, el envío es 5.
  7. El total es base + impuesto + envío.

La respuesta y GET /cart/:cartId/order expresan los montos en unidades, no en centavos. priceCheckout devuelve esos mismos montos y también los enteros en centavos (subtotalCents, discountCents, taxableCents, taxCents, shippingCents, totalCents, y los equivalentes en cada línea).

El pedido guarda el resultado. Un cambio posterior del precio no lo modifica. El carrito pasa a checked_out y un segundo cobro se rechaza. El inventario de cada producto baja en la cantidad de su línea. Si una línea no alcanza, no se descuenta ninguna. Dos cobros simultáneos pueden leer el mismo inventario antes de grabar y descontar de menos.

POST, PUT y DELETE de ítems no consultan checked_out. addItemToCart tampoco. Un ítem agregado después del cobro no entra en el pedido. GET /cart/:cartId/items sigue calculando con el precio vigente.

GET /cart/:cartId/order devuelve el pedido. Si el carrito no existe, o todavía no hay pedido, responde 404.

El cuerpo de un cobro sin cupón, de dos unidades a 100 con taxRate 0.07, tiene subtotal 200, discount 0, taxable 200, tax 14, shipping 0 y total 214. Con una unidad a 40 y taxRate 0, el envío es 5 y el total es 45. Con una unidad a 50 y taxRate 0, el envío es 0 y el total es 50.

Separación entre servidor real y aplicación aislada de Supertest

La API principal utiliza los prefijos /cart, /products y /categories, según el apartado Rutas canónicas. En tests/routes/cart.test.js, la aplicación Express aislada se configura así:

const app = express();
app.use(bodyParser.json());
app.use('/api/carts', cartRouter);

Por ello, el caso CP-07 utiliza GET /api/carts/99999/items en esa aplicación de prueba, mientras que el servidor normal expone las rutas de carrito bajo /cart. No se deben confundir ambos prefijos.

Base de datos y preparación de pruebas

En models/index.js, cuando NODE_ENV=test, Sequelize utiliza SQLite en memoria, con storage: ':memory:'. En otro entorno, la configuración utiliza ./db.sqlite. En tests/setup/testDb.js, initTestDb() realiza sequelize.sync({ force: true }) y closeTestDb() cierra la conexión.

Advertencia: force: true recrea las tablas de la base de datos conectada. Antes de ejecutar pruebas hay que establecer NODE_ENV=test; evitar ejecutarlas contra una base persistente de trabajo.

3.5 Riesgo residual de la API

Riesgo: sobreventa o descuento insuficiente de inventario por actualización perdida en el cobro concurrente.

  • Descripción. CheckoutService.checkout lee product.inventory dentro de la transacción, sin bloqueo ni actualización condicional, y luego guarda el valor absoluto (product.inventory -= quantity; product.save()). Dos cobros simultáneos sobre el mismo producto pueden leer el mismo stock; el segundo guardado sobrescribe el descuento del primero. El inventario queda mayor que el real y se pueden vender unidades que no existen.
  • Plausibilidad. Alta: el propio README lo reconoce en la sección Cobro ("Dos cobros simultáneos pueden leer el mismo inventario antes de grabar y descontar de menos"), el endpoint es público y la transacción de SQLite es DEFERRED, que no evita la lectura obsoleta.
  • Impacto. Alto: pedidos sin stock, cancelaciones manuales y reputación. Probabilidad: media con tráfico concurrente; baja con el volumen actual.
  • Evidencia. Identificado por inspección de código y de la regla documentada. No reproducido en esta entrega: no hay prueba concurrente.
  • Mitigación propuesta. Decremento relativo y condicional: UPDATE Products SET inventory = inventory - :qty WHERE id = :id AND inventory >= :qty, verificando las filas afectadas dentro de la transacción; prueba de concurrencia con Promise.all sobre SQLite de archivo.
  • Riesgo residual tras la mitigación. Bajo mientras la base sea SQLite de un solo proceso. Con varias instancias hará falta bloqueo a nivel de base de datos.

const SHIPPING_THRESHOLD_CENTS = 5000;
const SHIPPING_FEE_CENTS = 500;

const SHIPPING_THRESHOLD = SHIPPING_THRESHOLD_CENTS / 100;
const SHIPPING_FEE = SHIPPING_FEE_CENTS / 100;

function fromCents(cents) {
  return Number((cents / 100).toFixed(2));
}

function roundToInteger(value) {
  return Math.round(Number(value.toFixed(8)));
}

function toCents(amount) {
  return roundToInteger(amount * 100);
}

function assertCoupon(coupon) {
  if (coupon == null) {
    return;
  }
  if (typeof coupon !== 'object' || Array.isArray(coupon)) {
    throw new Error('Only one coupon is allowed');
  }
  if (coupon.type !== 'percent' && coupon.type !== 'fixed') {
    throw new Error('Coupon type must be percent or fixed');
  }
  if (typeof coupon.value !== 'number' || !Number.isFinite(coupon.value) || coupon.value <= 0) {
    throw new Error('Coupon value must be greater than zero');
  }
  if (coupon.type === 'percent') {
    if (coupon.value > 1) {
      throw new Error('Percent coupon cannot exceed 1');
    }
    if (typeof coupon.minSubtotal !== 'number' || !Number.isFinite(coupon.minSubtotal) || coupon.minSubtotal < 0) {
      throw new Error('Percent coupon requires a minimum subtotal');
    }
  }
}

function discountCentsFor(subtotalCents, coupon) {
  assertCoupon(coupon);
  if (coupon == null) {
    return 0;
  }
  if (coupon.type === 'percent') {
    const minCents = toCents(coupon.minSubtotal);
    if (subtotalCents < minCents) {
      throw new Error('Coupon minimum not met');
    }
    return roundToInteger(subtotalCents * coupon.value);
  }
  const discountCents = toCents(coupon.value);
  if (discountCents > subtotalCents) {
    throw new Error('Coupon exceeds subtotal');
  }
  return discountCents;
}

function allocateDiscount(lineSubtotals, discountCents) {
  const shares = new Array(lineSubtotals.length).fill(0);
  if (discountCents === 0) {
    return shares;
  }
  const subtotalCents = lineSubtotals.reduce((sum, cents) => sum + cents, 0);
  let allocated = 0;
  for (let i = 0; i < lineSubtotals.length; i += 1) {
    if (i === lineSubtotals.length - 1) {
      shares[i] = discountCents - allocated;
    } else {
      const proportional = roundToInteger(discountCents * (lineSubtotals[i] / subtotalCents));
      const share = Math.min(proportional, discountCents - allocated);
      shares[i] = share;
      allocated += share;
    }
  }
  return shares;
}

function priceCheckout(items, coupon) {
  if (!Array.isArray(items) || items.length === 0) {
    throw new Error('Cart is empty');
  }
  assertCoupon(coupon);

  const lines = items.map((item) => {
    if (!item || !Number.isInteger(item.quantity) || item.quantity <= 0) {
      throw new Error('Quantity must be a positive integer');
    }
    if (typeof item.unitPrice !== 'number' || !Number.isFinite(item.unitPrice) || item.unitPrice < 0) {
      throw new Error('Price must be zero or greater');
    }
    if (typeof item.taxRate !== 'number' || !Number.isFinite(item.taxRate) || item.taxRate < 0 || item.taxRate > 1) {
      throw new Error('Tax rate must be between 0 and 1');
    }

    const unitPriceCents = toCents(item.unitPrice);
    return {
      productId: item.productId,
      quantity: item.quantity,
      unitPriceCents,
      taxRate: item.taxRate,
      lineSubtotalCents: unitPriceCents * item.quantity,
    };
  });

  const subtotalCents = lines.reduce((sum, line) => sum + line.lineSubtotalCents, 0);
  const discountCents = discountCentsFor(subtotalCents, coupon);
  const shares = allocateDiscount(lines.map((line) => line.lineSubtotalCents), discountCents);

  const pricedLines = lines.map((line, index) => {
    const lineDiscountCents = shares[index];
    const taxableCents = line.lineSubtotalCents - lineDiscountCents;
    const lineTaxCents = roundToInteger(taxableCents * line.taxRate);
    return {
      productId: line.productId,
      quantity: line.quantity,
      unitPrice: fromCents(line.unitPriceCents),
      taxRate: line.taxRate,
      lineSubtotal: fromCents(line.lineSubtotalCents),
      lineDiscount: fromCents(lineDiscountCents),
      lineTax: fromCents(lineTaxCents),
      lineSubtotalCents: line.lineSubtotalCents,
      lineDiscountCents,
      lineTaxCents,
    };
  });

  const taxCents = pricedLines.reduce((sum, line) => sum + line.lineTaxCents, 0);
  const taxableCents = subtotalCents - discountCents;
  const shippingCents = taxableCents >= SHIPPING_THRESHOLD_CENTS ? 0 : SHIPPING_FEE_CENTS;
  const totalCents = taxableCents + taxCents + shippingCents;

  return {
    subtotal: fromCents(subtotalCents),
    discount: fromCents(discountCents),
    taxable: fromCents(taxableCents),
    tax: fromCents(taxCents),
    shipping: fromCents(shippingCents),
    total: fromCents(totalCents),
    subtotalCents,
    discountCents,
    taxableCents,
    taxCents,
    shippingCents,
    totalCents,
    lines: pricedLines,
    coupon: interpretedCoupon(coupon, discountCents),
  };
}

function interpretedCoupon(coupon, discountCents) {
  if (coupon == null) {
    return null;
  }
  if (coupon.type === 'percent') {
    return {
      type: 'percent',
      value: coupon.value,
      minSubtotal: fromCents(toCents(coupon.minSubtotal)),
    };
  }
  return {
    type: 'fixed',
    value: fromCents(discountCents),
  };
}

module.exports = {
  SHIPPING_THRESHOLD,
  SHIPPING_FEE,
  priceCheckout,
};

Reglas funcionales (A1) del README (especificación vinculante)

  • Envío: umbral 50, tarifa 5. Si la base imponible (subtotal − descuento) >= 50, envío 0; si < 50, envío 5.
  • priceCheckout(items, coupon) es pura: no toca la base de datos. Cada ítem es { quantity, unitPrice, taxRate }.
  • Cupón opcional. Si coupon es un arreglo o no es objeto → rechazar ("Only one coupon is allowed").
  • type: percent o fixed. Otro valor → rechazar.
  • value: número > 0. De lo contrario → rechazar.
  • percent: value fracción > 0 y <= 1. Exige minSubtotal >= 0. Si subtotal < minSubtotal → rechazar. Si == minSubtotal → aplica.
  • fixed: value monto > 0. Se redondea al centavo y se compara con subtotal. Si supera → rechazar. Si == → base queda en 0. Un cupón fixed no consulta minSubtotal.
  • No se acumulan cupones.
  • Orden de cálculo: 1. Precio unitario redondeado al centavo. 2. Subtotal de línea = precio × cantidad. Subtotal del pedido = suma de líneas. 3. Descuento sobre el subtotal. 4. Descuento repartido en orden de líneas, proporcional al subtotal de cada una, redondeado al centavo, sin pasar del descuento pendiente. Última línea recibe el resto. 5. Impuesto de línea = (subtotal de línea − descuento de línea) × taxRate, redondeado al centavo. Impuesto = suma. 6. Base = subtotal − descuento. Si base >= 50 → envío 0, si < 50 → envío 5. 7. Total = base + impuesto + envío.
  • Cantidad debe ser entero > 0. Precio >= 0. taxRate entre 0 y 1.
  • Respuesta en unidades, no centavos. priceCheckout también devuelve enteros en centavos.
